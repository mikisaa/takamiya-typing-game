# 09_test_plan.md — テスト計画書

本ドキュメントは、受入基準（`08_acceptance_criteria.md`）の達成を検証するためのテストケース（Test Cases）およびテスト実施計画を定義します。
Planning 時点におけるすべてのテストケースの初期ステータスは `[PENDING]` です。

---

## 1. テストカテゴリ & アプローチ

1. **Unit / Logic Tests (UT)**: タイピング判定エンジン（ローマ字表記揺れ・ASCII混在語）、動的走行時間モデル（文字数連動算出式）、スコア計算ロジック、設定値ローダーの単体検証。
2. **Animation / Scene Tests (ST)**: フォークリフト走行（動的時間連動）、成功/失敗アニメーション、背景進化、EXTRA演出の描画とタイミング検証。
3. **Integration / API Tests (IT)**: フロントエンドとGAS Web Appエンドポイント間のマスター取得、スコア送信、ランキング取得通信および排他制御の検証。
4. **Data Validation Tests (DT)**: Question Master v3（全180問）のCSVスキーマ、難易度別件数（60/60/60）、重複排除、文字数分布の完全性検証。
5. **E2E / Browser UI Tests (E2E)**: PCブラウザ上でのタイトルからゲームプレイ、リザルト、ランキング画面への一連のユーザーフロー検証。

---

## 2. テストケース一覧 (Test Cases)

- [TC-001] [PENDING] フォークリフト走行および2種タイマー動作の検証 ([AC-001])
  - **手順**: ゲームを開始し、出題ごとに算出された Per-Question Forklift Timer に従ってフォークリフトが等速走行し、Global Game Timer（90秒）が正常にカウントダウンすることを確認する。
  - **期待結果**: 2つのタイマーが独立して動作し、アニメーションが滑らかに描画されること。

- [TC-002] [PENDING] キーボード直接捕捉・ローマ字揺れ・ASCII混在語判定の検証 ([AC-002])
  - **手順**: 入力欄をクリックせず直接キーボードから「しちゅう」「安全帯よし」を入力する（「し」を `si` / `shi`、「ち」を `ti` / `chi` で入力）。また `AI`, `TQM`, `2S`, `4M3H`, `OPE-MANE` 等の英数混在語を大文字および小文字で入力する。ミスタイプキーを入力する。
  - **期待結果**: 入力欄フォーカス不要で入力が即座に反映され、異なる表記パターンおよびASCII大文字小文字がいずれも正常に受理され、ミスタイプ時に赤色フラッシュが表示されること。

- [TC-003] [PENDING] トラック到達前の入力完了とSUCCESS演出の検証 ([AC-003])
  - **手順**: Per-Question Forklift Timer 満了前（トラック到達前）に問題をタイピング完了する。
  - **期待結果**: フォークリフトが停止し、爪上の資材が荷台へ移動するアニメーションが再生され、「SUCCESS」表示とスコア・コンボ加算が行われ、450ms以内に次の問題がロードされること。

- [TC-004] [PENDING] タイムオーバー時のMISS演出とGlobal Timerペナルティ減算の検証 ([AC-004])
  - **手順**: 問題を入力せずフォークリフトをトラックへ到達（Per-Question Timer 満了）させる。
  - **期待結果**: トラック接触時の車体振動と資材落下アニメーションが実行され、「MISS」表示とともにコンボが0になり、Global Game Timer から難易度別ペナルティ（初級-3s/中級-4s/上級-5s）が減算されること。

- [TC-005] [PENDING] 難易度切り替えによる車両テーマと走行パラメータの検証 ([AC-005])
  - **手順**: 初級、中級、上級を切り替えてゲームを開始する。
  - **期待結果**: 初級=軽トラック、中級=4tユニック、上級=15tユニックのグラフィックおよび難易度別KPSパラメータ（2.0 / 3.2 / 4.5）が正しく反映されること。

- [TC-006] [PENDING] 練習モードと本番モードの動作仕様の検証 ([AC-006])
  - **手順**: 練習モードと本番モードでそれぞれプレイを完了する。
  - **期待結果**: 練習モードではスコア送信が行われず、走行時間が本番の1.5倍の余裕時間（`practiceMultiplier = 1.5`）で動作し練習結果が表示される。本番モードでは90秒Global Timer、スコア集計、リザルト画面表示、スプレッドシートへの記録が正しく行われること。

- [TC-007] [PENDING] 7種類の仮設足場資材スプライトの出現検証 ([AC-007])
  - **手順**: 複数回問題を解き、爪上の資材グラフィックを確認する。
  - **期待結果**: 支柱、手摺、建枠、布板、筋交、ジャッキベース、小物資材パレットの全7種が正常に描画され、ランダムに出現すること。

- [TC-008] [PENDING] 正解数に応じた背景建設発展の段階的成長検証 ([AC-008])
  - **手順**: 0問、3問、7問、12問、18問、25問、33問と正解を重ねる。
  - **期待結果**: 更地 ➔ コンテナ ➔ 家 ➔ ビル ➔ 高層ビル ➔ 東京タワー ➔ スカイツリーへと背景構造物が順次建設・発展すること。

- [TC-009] [PENDING] EXTRAステージ移行と動的オブジェクト出現の検証 ([AC-009])
  - **手順**: 33問正解後にゲームを継続し、背景の動的演出を確認する。
  - **期待結果**: EXTRAモードへ移行し、都市背景に旅客機、ヘリコプター、風船、スカイダイビング、虹が表示され、同時表示数が最大3個以内に制御されること。

- [TC-010] [PENDING] 連続正解によるCOMBO倍率とTIME BONUS付与の検証 ([AC-010])
  - **手順**: ノーミスで15問連続正解し、Global Game Timer とスコア倍率を確認する。途中ミスタイプを発生させる。
  - **期待結果**: 15 COMBO達成時にGlobal Game Timer に+5秒加算され、スコア倍率が上昇すること。ミスタイプ時にCOMBOが直ちに0へリセットされること。

- [TC-011] [PENDING] 本番リザルト画面の集計値表示の検証 ([AC-011])
  - **手順**: 本番モードを終了し、リザルト画面の各表示項目（Score, 正解数, 入力文字数, ミス数, Accuracy, MaxCombo, WPM）を確認する。
  - **期待結果**: 確定計算式通りのスコアおよび各指標が正確に集計・表示されること。

- [TC-012] [PENDING] 月間・歴代ランキングの表示と自己ベスト集約の検証 ([AC-012])
  - **手順**: ランキング画面を開き、「今月」「歴代」および難易度タブを切り替える。同一プレイヤーで複数回スコアを送信した状態を確認する。
  - **期待結果**: 各プレイヤーの最高スコアのみが抽出され、期間・難易度別に上位20件が正しくソート表示されること。

- [TC-013] [PENDING] 自由入力プレイヤー名、ブラウザ記憶、およびクロスブラウザ解決の検証 ([AC-013])
  - **手順**: 本番モード設定画面で名前を入力してゲーム開始、リロード後の自動補完、別名への編集上書き、別ブラウザでの同一名（全角空白/大文字小文字違い含む）入力時のスコア送信、練習モードでの入力欄非表示を検証する。
  - **期待結果**: 前回名が安全に復元され、未登録名は新規PlayerIDが生成され、既存名（正規化一致）は同一PlayerIDが再利用され、練習モードでは名前入力なしで正常にプレイできること。

- [TC-014] [PENDING] Question Master v3 (全180問) のロードとデータ完全性の検証 ([AC-014])
  - **手順**: `takamiya-typing-game-master-v3.csv` をロードし、行数、カラム構造、難易度別件数（初級60/中級60/上級60）、ID重複の有無をテストする。
  - **期待結果**: 180問すべてが正常にロードされ、ID重複ゼロ、必須フィールド欠落ゼロで出題プールに反映されること。

- [TC-015] [PENDING] GAS APIエンドポイント通信の検証 ([AC-015])
  - **手順**: 初期ロード時のGET通信、スコア送信時のPOST通信、ランキング取得時のGET通信を実行する。
  - **期待結果**: 適切なJSONレスポンスが返却され、ゲームプレイ中の不要な通信が発生しないこと。

- [TC-016] [PENDING] 動的走行時間モデル（文字数連動）と難易度階層の検証 ([AC-016])
  - **手順**: 初級（短い問題・長い問題）、中級、上級（短い問題・長い問題）において算出される `allowedTime` をテストする。また同一文字数（20文字）における3難易度の時間を比較する。
  - **期待結果**: 文字数が長いほど `allowedTime` が合理的に延長され、min/max clamp が正常に機能し、同一文字数において「初級 > 中級 > 上級」の時間が厳格に維持されること。

- [TC-017] [PENDING] 60fpsゲームループのフレームレート安定性検証 ([AC-017])
  - **手順**: ブラウザの開発者ツールでFPSパフォーマンスをプロファイリングする。
  - **期待結果**: 60fps前後で安定して描画され、タイピング時の入力遅延や画面のカクつきが発生しないこと。

- [TC-018] [PENDING] GAS入力検証およびFormula Injection防止の検証 ([AC-018])
  - **手順**: プレイヤー名に `=1+1`, `@SUM(A1:A5)` 等の特殊文字を指定したスコア登録ペイロードをGASへ送信する。
  - **期待結果**: 先頭に `'` が付与されて安全にスプレッドシートへ文字列として格納され、数式として実行されないこと。

- [TC-019] [PENDING] LockServiceによる同時書き込み競合制御の検証 ([AC-019])
  - **手順**: 複数クライアント（または並列HTTPリクエスト）から同時にスコア送信を実行する。
  - **期待結果**: LockServiceにより直列化され、すべてのレコードが欠落なくScoresシートへ追記されること。

- [TC-020] [PENDING] デスクトップ解像度レスポンシブ表示の検証 ([AC-020])
  - **手順**: ブラウザウィンドウを 1920x1080, 1366x768, 1280x720 などに変更して表示を確認する。
  - **期待結果**: ゲーム画面やUI要素がはみ出さず、適切に中央配置・リサイズされること。

- [TC-021] [PENDING] 静的ホスティング配信環境適合性の検証 ([AC-021])
  - **手順**: 静的Webファイル群（HTML/CSS/JS）をローカルサーバーまたはGitHub Pagesで配信してアクセスする。
  - **期待結果**: ビルドサーバーやNode.jsランタイムなしにブラウザ単体で完全に動作すること。
