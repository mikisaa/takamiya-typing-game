# 08_acceptance_criteria.md — 受入基準書

本ドキュメントは、アプリケーションが満たすべき受入基準（Acceptance Criteria）を定義します。
Planning 時点におけるすべての受入条件の初期ステータスは `[PENDING]` です。

---

## 1. 機能要件受入基準 (Functional Acceptance Criteria)

- [AC-001] [PENDING] 2D横スクロールゲームプレイの基本動作 ([FR-001])
  - ゲーム開始後、画面左端からフォークリフトがトラックに向かって滑らかに走行を開始し、タイピング完了またはトラック到達まで走行し続けること。

- [AC-002] [PENDING] タイピング入力捕捉とローマ字入力判定 ([FR-002])
  - 入力フォームへのフォーカス操作なしにキー入力が直接捕捉され、問題の日本語文・ローマ字ターゲットに対して正しく判定が行われること。
  - 「し (shi/si)」「ち (chi/ti)」「つ (tsu/tu)」「じゅ (ju/zyu/jyu)」等の複数ローマ字入力パターンがいずれも正しく受理され、ミスタイプ時に赤色フィードバックが表示されること。

- [AC-003] [PENDING] 積込成功演出の実行と次問題移行 ([FR-003])
  - トラック到達前に単語入力が完了した場合、フォークリフトが停止し、爪上の資材が荷台へ移動するアニメーションが実行され、「SUCCESS」表示とスコア・コンボ加算が行われた後、テンポを損なわず450ms以内に次の問題へ移行すること。

- [AC-004] [PENDING] タイムオーバー・失敗演出とペナルティ適用 ([FR-004])
  - 入力完了前にトラックへ到達した場合、トラック接触時の振動と資材落下のアニメーションが実行され、「MISS」表示とともにコンボがリセットされ、制限時間から難易度別ペナルティが減算されて次の問題へ移行すること。

- [AC-005] [PENDING] 難易度別の車両テーマと走行速度の切り替え ([FR-005])
  - 初級（軽トラック）、中級（4tユニック）、上級（15tユニック）の難易度選択に応じて、積込先トラックのPixel Artグラフィックおよびフォークリフトの走行制限時間（8.0s / 6.0s / 4.5s）が正しく切り替わること。

- [AC-006] [PENDING] 練習モードと本番モードの動作分離 ([FR-006])
  - 練習モードではスコア送信が行われずタイピング練習と結果確認が行えること。本番モードでは90秒の制限時間、スコア・コンボ計算、リザルト画面表示、スプレッドシートへのランキング登録が正しく実行されること。

- [AC-007] [PENDING] 7種類の仮設足場資材のランダム出現 ([FR-007])
  - 支柱、手摺、建枠、布板、筋交、ジャッキベース、小物資材パレットの7種類の資材アセットがフォークリフトの爪の上に視認可能なPixel Artとしてランダムに出現すること。

- [AC-008] [PENDING] 正解数に応じた7段階の背景建設発展 ([FR-008])
  - 正解数の累積に応じて、更地 ➔ コンテナ ➔ 家 ➔ ビル ➔ 高層ビル ➔ 東京タワー ➔ スカイツリーへと背景都市が段階的に成長・組み上がっていくこと。

- [AC-009] [PENDING] スカイツリー完成後のEXTRAステージ動的演出 ([FR-009])
  - スカイツリー完成後（33問正解後）にEXTRAモードへ移行し、都市背景に旅客機、ヘリコプター、風船、スカイダイビング、虹の動的演出が同時3個以下の範囲でランダムに発生し、ゲームプレイが継続できること。

- [AC-010] [PENDING] COMBO加算とTIME BONUSの付与 ([FR-010])
  - 連続正解によりCOMBO数とスコア倍率が上昇し、15 COMBOごとに+5秒のTIME BONUS（最大+30秒まで）が残り制限時間に加算されること。ミスタイプ発生時は直ちにCOMBOが0にリセットされること。

- [AC-011] [PENDING] プレイ終了後のリザルト画面集計表示 ([FR-011])
  - 本番プレイ終了時に、Score、正解数、入力文字数、ミス数、正確率（Accuracy）、Max Combo、プレイ時間、難易度、PlayedAt、WPMがリザルト画面に正確に集計表示されること。

- [AC-012] [PENDING] 月間・歴代ランキングの表示と自己ベスト集約 ([FR-012])
  - ランキング画面で「今月」「歴代」および難易度（初級・中級・上級）を切り替えて閲覧でき、同一プレイヤーの自己最高スコアのみが抽出されて上位20件が表示されること。

- [AC-013] [PENDING] プレイヤーマスターからの名前選択 ([FR-013])
  - 設定画面でスプレッドシート上の有効なプレイヤー一覧（Player master）から名前を選択してプレイを開始できること。

- [AC-014] [PENDING] データ駆動型の問題データ管理と出題 ([FR-014])
  - 問題データが外部定義可能なJSON構造として分離されており、難易度やカテゴリに応じた問題が正しくロード・出題されること。

- [AC-015] [PENDING] GASバックエンドとの安全なAPI通信 ([FR-015])
  - 初期マスター取得、本番スコア登録、ランキング取得のAPI通信がGAS Web Appとの間で正常に完了し、ゲーム中の不必要な常時通信が発生しないこと。

- [AC-016] [PENDING] ゲーム設定値の一元管理と調整容易性 ([FR-016])
  - 速度、制限時間、ペナルティ、ボーナス閾値等のゲームバランス設定値がConfigモジュールに集約され、コード本体を改修することなく設定変更が反映されること。

## 2. 非機能要件受入基準 (Non-Functional Acceptance Criteria)

- [AC-017] [PENDING] フロントエンド描画のスムーズさと60fps維持 ([NFR-001])
  - ゲームプレイ中、`requestAnimationFrame` を利用したアニメーションがフレーム落ちなくスムーズに描画され、入力遅延なく快適にタイピング操作できること。

- [AC-018] [PENDING] GAS側入力バリデーションと数式インジェクション防止 ([NFR-002])
  - クライアントからの不正なスコア値（負の値や異常な文字数）がGAS側で拒否され、先頭に特殊文字（`=`, `+`, `-`, `@`）を含むプレイヤー名が安全にエスケープされてスプレッドシートへ記録されること。

- [AC-019] [PENDING] LockServiceによる同時書き込み競合防止 ([NFR-003])
  - 複数クライアントから同時にスコアが送信された場合でも、GASの排他制御によりデータの上書き破壊や欠落が発生せず安全に追記されること。

- [AC-020] [PENDING] デスクトップブラウザ解像度におけるレイアウト整合性 ([NFR-004])
  - 一般的なPCデスクトップブラウザ解像度において画面の重要要素がはみ出さず、適切にレイアウトが保持されること。

- [AC-021] [PENDING] 静的ホスティング配信と環境整合性 ([NFR-005])
  - 静的Webファイル群（HTML/CSS/JS）としてGitHub Pages等から配信可能であり、不要な外部SaaS依存が存在しないこと。
